Architecture decisions

Edited 4m ago by Dara K.

We're splitting checkout into three services: cart, payment, and fulfillment. This keeps the payment path auditable on its own without dragging in cart logic.

Why not one service

  • Payment needs a stricter deploy cadence than cart
  • Fulfillment has a completely different scaling profile

See architecture.canvas in this project for the diagram this describes. This document is independently edited — it is not generated from or synced to the canvas.
